# Android root access (experimental)

[简体中文](README.md) · **English**

Connect an installed official Grok Bot Android app to a self-hosted Host using root and adb. The tool patches the app's private Expo cache and keeps the installed APK and its signature. It does not produce a standalone patched APK.

HTTPS pairing, listing and creating conversations, sending text and displaying replies have been verified on one Android 11 / arm64 test device. Other devices and Android versions remain unverified.

## Requirements

- Official `ai.x.grok.bot` **1.19.1 (3050)** installed for the primary Android user (user 0), opened normally at least once. Exact base APK and embedded Hermes 98 hashes are checked by [hermes.py](tools/hermes.py).
- An already rooted phone, authorized adb, Python 3.10+ and Android platform-tools on the computer.
- Host built from source containing Android pairing support, with a working model configuration.
- The same HTTPS origin accessible from the phone and computer. The phone must trust its certificate. Set `GROKBOT_PUBLIC_URL` to that origin.

Disable Google Play automatic updates for this app. Exclude Grok Bot from LSPosed modules: even a module with no hooks crashed this tested device/app combination. The tool does not change LSPosed settings or reboot the phone.

Prefer HTTPS with a certificate already trusted by Android. Without a domain, see the [private SSH and HTTPS guide](SSH-TLS.md) (Chinese). Its optional system CA installer is limited to Android 11 and needs the device owner's authorization. A normal Android user certificate is insufficient for this tested app.

## Install and pair

Run from the repository root; replace `adb` if it is not on PATH. Add `--serial <serial>` before the subcommand when several devices are connected.

```sh
adb devices
python android/tools/root_cache.py --adb adb diagnose
python android/tools/root_cache.py --adb adb connect --host https://bot.example.com --name "Android phone"
```

Create a fresh six-character code under Devices & Notifications in the Host administration page. Enter it at the terminal prompt, not in command-line arguments. Use an HTTPS origin without `/admin`, `/api` or `/v1`. Add `--ca-cert <CA.pem>` to trust a private CA for the computer's pairing request only; this does not install phone trust.

The installer stops the app, validates and backs up its Expo database, installs the generated cache and checks the process mapping after startup. It retries one cold start if necessary. After `installed: true` and `patchedBundleMapped: true`, open a Bot and ask it to reply with `ANDROID_HOST_OK` without calling tools. Confirm the reply appears and remains after reopening the conversation. This uses your configured model quota; the installer itself never sends chat messages.

## Check, update and restore

```sh
python android/tools/root_cache.py --adb adb status
python android/tools/root_cache.py --adb adb diagnose
python android/tools/root_cache.py --adb adb refresh
```

`status` checks the supported app's process mapping and backup availability. `diagnose` reads APK compatibility and backup integrity even after an unsupported update, without reading the device token. Its `supported` field concerns the pinned APK recipe, not general device compatibility.

`refresh` replaces a known older patch while preserving its pairing, original recovery backup and current catalogue records. It attempts rollback if replacement or startup fails. The `gateway-send-v2` recipe fixes the cloud sender that previously reported “not logged in” despite successful Host pairing; it selects the app's existing `gateway.sendPrompt` implementation.

To leave the experiment, **before updating the official APK**:

1. Revoke the phone in Host administration.
2. Run `python android/tools/root_cache.py --adb adb restore`.
3. Confirm `restored: true`, then use `status` to check that the patched cache is no longer mapped.

Restore replaces the saved Expo catalogue and removes this tool's credential, bundle and backup. It does not revoke the server token or delete Host conversations. Use `refresh`, not restore, when updating the patch and keeping pairing.

If the APK has already changed, run `diagnose`, preserve its output and the private backup, revoke the device on Host, and stop using this recipe. **Cross-version automatic recovery is not supported.** A maintainer must inspect the new runtime/schema before migration or cleanup. Do not delete the database, clear app data or bypass the version/hash checks. Unknown OTA records also cause install/refresh to stop for inspection.

## Sharing and limits

Share the source tools and instructions. Each user supplies the supported original app and pairs independently. **Do not share `connection.json`, the generated HBC, or copied application data:** the HBC contains that phone's device token. Credentials and generated bytecode are processed in memory and stored only in the phone's private directory; desktop temporary files hold database snapshots.

Google Play updates and Expo OTA are separate. Expo can still supersede the local cache even with Play automatic updates disabled. This Android experiment does not implement official-network or telemetry isolation. Push notifications are not implemented; attachments, voice, approval UI, desktop viewing, network transitions and long-term stability remain unverified. Keep any required SSH tunnel running.

The incompatible LSPosed prototype is archived under [research/lsposed](research/lsposed/README.md); it is not the installation path and its Java recipe lacks the send fix.

## Validation

```sh
python -m unittest discover -s android/tests -p 'test_*.py' -v
node --test host/tests/android-pairing.test.mjs host/tests/admin-origin.test.mjs
# Linux with Host dependencies installed, or an isolated Host test image:
node --test host/tests/android-http.test.mjs host/tests/admin-origin-http.test.mjs
```

Set `PROKBOT_TEST_BUNDLE` to a locally extracted original bundle and `PROKBOT_TEST_OPENSSL` if OpenSSL is not on PATH. Tests requiring missing inputs explicitly skip; skips are not passes. Tests cover patch integrity, sender selection, catalogue consistency, credential preservation and rollback, unsupported-version diagnostics, TLS and HTTP authentication/RPC/SSE/revocation. Test data and upstreams are isolated from production.
